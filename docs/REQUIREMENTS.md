# 需求清单（v0.1 落地版）

> 这份是"要做什么"的清单，不是设计。设计见 `DESIGN.md`。每条都要求可判定。

## 0. 一句话

把本机 Hana 接入 OpenViking，让不同机器上的 OpenHanako、以及自托管的其它 agent（Hermes）
共用同一份记忆与技能；常驻开销与本机无关、与远端库规模无关，连不上时等于没装。

## 1. 记忆（自动，每轮）

- **R1 召回**：每轮把用户这句话送去 `search(mode="context", peer_scope=all)`，把返回的
  记忆块注入本轮上下文。阈值 0.35、预算 2000 token，由服务端裁剪。
- **R2 写回**：轮次结束后把本轮新增对话写回（createSession → messages/batch → commit）。
  同一 peer + 同一会话幂等；增量用**内容指纹**做游标，不用长度。
- **R3 身份**：`peer = <prefix>-<agentDir>`，一个 agent 一个门牌；可开关"合并记忆"
  把同机所有 agent 折成一个 peer。
- **R4 零成本**：总闸关 / 只读 / 身份不全 / 服务器不可达，一律在碰数据之前短路；
  超时 1.5s，失败不重试、不报警、不影响本轮。

## 2. 技能（检索，非索引）

- **S1 不列清单**：任何时刻都不把技能库的全量列表注入上下文。
- **S2 子会话路由**：子会话开始时用分派提示检索一次（`skills/find`，阈值 0.45，≤5 条），
  得到"任务工作集"，以 L0 粒度（名字 + 何时用 + 怎么取全文）注入，粘住到会话结束。
- **S3 主会话只留指针**：主会话不自动注入工作集，只有一句恒定的能力指针（约 40 token）。
- **S4 按需读取**：`openviking_skill_load(name)` 取 L2 正文与附件清单，永远不自动注入全文。
- **S5 人工补丁**：功能面板里按需求搜索、选中，然后二选一：
  - 加入本会话技能列表（L0 进系统区，会话级生效）
  - 直接加载完整技能（全文进变动区，现在就照做）
- **S6 上行**：本机 `<HANA_HOME>/skills/**` 可推送为 OpenViking 技能包（手动触发，不自动）。
- **S7 规模无关**：远端技能灌到 1000+ 后，单轮注入 token 不随库规模增长；
  20 轮对话里技能检索调用只出现在任务边界。
- **S8 附件与脚本**：技能包可带脚本/二进制附件（OpenViking 只存不跑）。
  默认**不自动下载、不自动执行**；用户确认后才落到 App dataDir，落盘前校验 sha256，
  然后把实际路径告诉模型，由模型用自己持有的工具执行。插件不代跑任何远端代码。
- **S9 执行授权（三通道，职责不重叠）**：
  | 角色 | 做什么 | 不做什么 |
  |---|---|---|
  | 插件 | 拉取、校验 hash、落地、给路径 | 不执行、不弹自己的审批框 |
  | 审查者（可选子代理） | 静态摘要：读写哪些路径 / 是否联网 / 是否起外部进程 / 是否混淆；输出固定字段 | 不拿执行权，结论只能是"建议" |
  | 宿主 | 工具执行审批（permissionMode） | — |

  - **不另造审批层**：执行走模型手上的工具，审批自然发生；再造一个闸会和宿主那个互相躲。
  - **一次一授权**，不做"以后都允许"，除非用户明确信任该 peer。
  - **信任分级**：自家 peer 的技能审一次、按 hash 记住；陌生来源每次都审。
  - **注入风险**：不可信脚本本身就是提示注入载体（注释里写"忽略以上指令"就能污染审查者）。
    所以审查者必须上下文隔离、只输出结构化字段，且不能把脚本原文带回主上下文。

## 3. 代价与可见性

- **C1 代价提示**：面板每次激活前报出"重建多少 token 前缀"（实测值）与"本会话缓存命中率"，
  并标明哪些是推断。
- **C2 可回看**：状态卡保留上一次激活的实测代价（重建 token 数、首字延迟、命中率变化）。
- **C3 日志**：每轮记命中分数、注入了谁、占多少 token、跳过原因。没有这份日志则不调参。

## 4. 工程约束

- **E1 形式**：v2 App（`manifestVersion: 2`），能力词逐项声明，不申请 full-access。
- **E2 密钥**：API Key 只存 App 设置（`sensitive: true`），不进仓库、不进日志、不进 UI 回显。
- **E3 网络**：只允许 manifest 白名单内的主机；私网地址显式 `allowLocalhost`。
- **E4 单写者**：正式启用后必须停用 v1 插件 `openviking-memory`，否则记忆会写两遍。
- **E5 可测**：`dev/smoke.mjs` 离线跑（mock fetch），不联网也能验证客户端、身份、指纹游标。
- **E6 不代跑远端代码**：技能附件里的一切可执行内容，都是"带 hash 的内容"，不是"要执行的程序"。
  插件只负责下载与校验，执行权永远在模型当前会话的工具集里。
- **E7 审查不是授权**：审查只能降风险，不能当权限用。硬边界是宿主的执行审批与工具集，不是任何人的判断。

## 5. 明确不做（v0.1）

- 不改写 Hana 本地记忆库（facts.db / memory.md）。
- 不做点对点同步、不做冲突合并。
- 不做技能落盘安装（只提供内容，由 agent 或用户落地）。
- 不做技能市场、不做浏览式 UI。
- 不做多账户 / 多租户切换。

## 6. 验收（五条，可判定）

1. 新会话问一件只有别的 peer 知道的事，回答里出现该事实，且该轮写回日志为 ok。
2. 写回后 OpenViking 侧能查到 `mbp-*` peer 的记录，主力机侧能召回。
3. 断网后首字延迟增加 < 100ms，日志只有短路记录、无报错。
4. 本机新建 skill 推送后，在另一 agent 侧能检索到并读到正文。
5. 远端技能灌到 1000+ 后，单轮注入 token 与检索次数不随之增长。

## 7. 第一步（本轮）

先装一个**探针版**：三个接缝各记一行日志，不注入任何东西。要拿回四个事实：

- `agent/before-start` 是每轮一次还是每会话一次，注入的 message 会不会留在会话历史里。
- `provider/before-request` 在一轮里被调用几次，payload 的结构是什么。
- 子会话（分派出去的任务）会不会同样触发这两个接缝。
- `agent/settled` 里能不能拿到 sessionId / sessionPath。

四个事实决定了注入位置和预算怎么写，比任何推测都可靠。
